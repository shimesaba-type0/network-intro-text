序章　ネットワークが生まれるまで

この本の読み方

この本では、同じ形の箱をくり返し使って情報を整理しています。箱の色と形がそのまま「これは何を書いてある部分か」を表しているので、慣れてしまえば、いちいち説明書きを読まなくても、見た目だけで判断できるようになります。

以下は、本書に登場する5種類の箱です。一度だけここで見ておいてください。

1. 一言要約（黄色の角丸ボックス）

通信の役割を7つの階層に分けて整理した設計図が、OSI参照モデルです。

そのページで扱う内容を1文に凝縮したものです。時間が無いときは、この黄色い箱だけを拾い読みしていっても、本書全体の大枠はつかめます。

2. スライド風要約（グレーの枠）

なぜ階層化するか

  • 役割ごとに問題を切り分けられる
  • どこが壊れているか特定しやすい

一言要約をもう一段具体的にした、3つ程度の観点への分解です。ここまで目を通せば、詳細に進まなくても内容の大半は把握できます。

3. 詳細（区切り線の下の本文）

スライド風要約で示した内容を、実際の文章として丁寧に説明していく部分です。仕組みや背景をきちんと理解したいときに読む本文で、複数ページに渡ることもあります。特別な箱の形はなく、この段落のような通常の本文として続きます。

4. 実務メモ（琥珀色の左線）

現場で実際に起きる事故や、著者自身が経験した具体的な事例です。

読み飛ばしても、そのページの本筋の理解には支障ありません。実務での「あるある」を知っておきたい方向けです。

5. クラウドでは（青緑色の左線）

クラウドで言うと、Network Load BalancerはL4、Application Load BalancerはL7を意識した機能を持ちます。

その概念が、実際のクラウドサービスでどう現れるかを紹介します。読者がそのサービスを使っていなくても、事実として読める内容にしています。

ネットワークが生まれるまで

（本文はこれから執筆。以下は展開の流れのメモ）

  1. スタンドアロン → 「つなぐ」発想
  2. つなぐと「あて先」が要る → アドレスの誕生
  3. 複数台を1箇所に → ダムハブ（リピーターハブ）登場。まだ1つの共有の土俵
  4. 共有の土俵には「順番」が要る → トークンリング／CSMA/CDが主流に
  5. 台数増加で衝突が深刻化 → L2スイッチ登場。全二重化と合わせ衝突がほぼ消える（第3章で回収）
  6. サービスを提供するサーバーの登場（クライアントサーバーモデル）
  7. サーバーは貴重 → 1台で複数サービス → 区別のため窓口＝ポート番号が誕生（第7章で回収）
  8. ネットワーク同士をつなぎたい → IPアドレスとルータの誕生
  9. つないだら「入れたくない相手」も → アクセス制御という発想
  10. 機器増加でコスト圧力 → スイッチを論理分割する発想（第6章で回収）
