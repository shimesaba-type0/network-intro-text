# 執筆メモ（章ごとの構成ノート）

このファイルはビルド対象（`vivliostyle.config.js`の`manuscript`配列）に含まれない、
執筆者・AIエージェント向けの作業メモ。目次v3で確定した構成の決定内容と、各章の執筆時に
参照する技術メモを集約する。

以前は各章の`manuscript/*.md`末尾にHTMLコメント（`<!-- ... -->`）として同じ内容を
埋め込んでいたが、VFM（Vivliostyle Flavored Markdown）は行頭から始まる複数行の
HTMLコメントブロックを確実には無視してくれず、コメント内部が通常のMarkdownとして
解釈されて本文に漏れ出る不具合が判明した（Issue #5）。構成メモ・TODOは今後すべてこの
外部ファイルに集約する運用とし、`manuscript/*.md`側にはコメントを残さない。

## 原稿中の注記マーカーの凡例

執筆時に本文中（またはこのファイル内のメモ）で使う目印。読者向けの表記ではなく、
執筆者・AIエージェント向けの内部マーカー。

- **【伏線】**: 後の章で回収予定の要素であることを示す執筆者用の目印。
- **【Tips】**: 「クラウドでは」ボックス（`box-callout cloud`）に載せる候補。
- **【実務】**: 実務メモボックス（`box-callout jitsumu`）に載せる候補。
- **【検討中】**: まだ扱う深さ・扱い方が確定していない項目。

## 表記ルール（本文執筆時）

- 挿入句を挟むダッシュは`――`（水平線、U+2015を2つ）に統一する。`──`（罫線素片、U+2500）は
  使わない（序章の初稿で混在していたのを統一した）。
- 数字は原則アラビア数字を使う（「1台」「3台、4台」等）。見出しなど文芸的な言い回しの中でのみ
  漢数字を許容する（序章の見出し「一台だけでは、何も始まらない」が該当）。
- 一人称複数は「わたしたち」とひらがな表記する（序章で初出、以降の章もこれに合わせる）。

## 各章メモ

### はじめに

- 「この本の読み方」（5種類の箱の凡例）を配置済み（Issue #8）。序章（物語本文）とは
  役割が異なるため、独立したファイルとして分離している。

### 序章

- 「ネットワークが生まれるまで」は本文化済み（`manuscript/01-序章.md`）。史実の年表をそのまま
  なぞったものではなく、技術が生まれた順番やきっかけも分かりやすさを優先して大胆に組み立て
  直した物語である旨を本文冒頭に明記した上で、以下の流れに沿って書いている。

  1. スタンドアロン → 「つなぐ」発想（同軸ケーブルで2台を接続）
  2. つなぐと「あて先」が要る → アドレスの誕生
  3. 台数増加 → 同軸ケーブルを延長したバス配線 → 距離の限界 → リピーター登場
  4. バス上でトークンを回す「トークンバス」誕生。全員に届くのでアドレスで自分宛て以外は破棄
     （2.の伏線をここで回収）
  5. 共有バスの弱点（長い1本のケーブルがどこかで切れると全体停止）→ 集線装置（MAU、詳細略）
     に個別配線を集約し、内部で輪とトークンを維持する「トークンリング」へ
  6. トークンリングの弱点（待ち時間の不確実性・コスト）→ 順番を待たずとりあえず送る
     「CSMA/CD」誕生
  7. CSMA/CD陣営も同じ共有バスの弱点に直面 → ダムハブ（リピーターハブ）登場。まだ1つの共有の土俵
  8. 台数増加で衝突が深刻化 → L2スイッチ登場。MACアドレステーブルで宛先ポートのみに転送
     （衝突ドメインを1ポート単位に）。同軸→より対線（2対のみ使用）の移行で全二重も実現し、
     衝突がほぼ消える（第3章で回収）
  9. サービスを提供するサーバーの登場（クライアントサーバーモデル）
  10. サーバーは貴重 → 1台で複数サービス → 区別のため窓口＝ポート番号が誕生（第7章で回収）
  11. ネットワーク同士をつなぎたい → IPアドレスとルータの誕生
  12. つないだら「入れたくない相手」も → アクセス制御という発想
  13. 機器増加でコスト圧力 → スイッチを論理分割する発想（第6章で回収）

- 伏線: トークンバス/トークンリング→CSMA/CD→ダムハブ→L2スイッチ→全二重化（第3章で回収）、
  ポート番号が必要になった経緯（第7章で回収）、スイッチの論理分割という発想（第6章で回収）。
- 「共有バスの1本のケーブルがどこかで切れると全体が止まる」という弱点は、トークンバスから
  トークンリング（集線装置化）への転換と、CSMA/CDからダムハブへの転換の、両方に共通する
  動機として使っている（当初は「1台の電源断でリレーが途切れる」という説明を検討したが、
  著者レビューでバス配線ではその弱点が成立しないと指摘があり、この形に修正した）。
- CSMA/CDの記述は「回線が空いているかを確認してから話す」（キャリアセンス）と「ぶつかったら
  ランダムな時間待ってやり直す」（衝突検知後のバックオフ）の両方を含む形にしている。
- L2スイッチの節は、MACアドレステーブル（送信元アドレスの学習→宛先アドレスでの転送先判定）
  という具体的な仕組みで「衝突ドメインを1ポート単位にできた理由」を説明し、加えて
  同軸→より対線（4対中2対使用、送受信が別経路になり全二重が可能に）という配線面の変化にも
  触れている。「衝突ドメイン」という用語は第3章での回収を前提にここで先出ししている。
- ネットワーク模式図を7点（単体PC、バス配線、集線装置＋内部トークンリング、CSMA/CD衝突、
  ダムハブ接続、MACアドレステーブル、半二重/全二重比較）追加済み。ソースは
  `assets/images/00-*.svg`。旧`00-token-ring-topology.svg`（単純なリング型トポロジー図）は、
  集線装置経由の構成に差し替えたため削除した。`.drawio`ソースを持たない例外
  （詳細は`docs/drawio-to-svg.md`）。

### 第2章（2-6メモ: PoE）

- PoEの規格（802.3af/at/bt等）とスイッチ側の電力予算（PoE budget）の関係を実務メモボックスで
  簡潔に紹介する。規格表の丸暗記ではなく、「スイッチのPoE予算を超えるとどうなるか」という
  実務上の注意点にフォーカスする（決定ログ#6）。

### 第3章（3.3メモ: 衝突ドメインの表記）

- 序章の伏線回収として、3.3節の見出しは「コリジョンドメインとブロードキャストドメイン」
  （カタカナ語）で既に確定している一方、序章側では「衝突ドメイン」（漢字表記）で先出しして
  いる。3.3節を本文化する際は、序章の表記を踏襲するか、「衝突ドメイン（コリジョンドメイン）」
  のように両方を併記して読者が同じ概念だと分かるようにするか、どちらかに決めること。

### 第5章（5-4メモ: OSPF）

- 冒頭の幕間「経路が増えて面倒になった話」は、以下の流れを本文化する。

  - 複数ルータのスタティックルート管理が面倒に → ダイナミックルーティングへの伏線
  - 組織間接続の広がり → IX → 組織ごとの事情を扱う柔軟な仕組み＝BGPへの伏線
  - ネットワークが大学間・組織間を越えて世界規模に

- OSPFはエリア0を中心とした概念（エリア分割の目的、LSAが存在すること程度）までとし、設定手順や
  マルチエリア設計には踏み込まない（決定ログ#5）。BGPへの橋渡しとして「組織内で完結する
  ダイナミックルーティングの代表例」という位置づけで扱う。

### 第7章

- 7.5「ARPとICMP」は目次v3の確定事項としてこの位置に置くが、ARP/ICMPはトランスポート層
  （L4）のプロトコルではない。第1章のOSI参照モデルの枠組みと矛盾して見えないよう、
  執筆時に「通信の診断・補助という役割でこの章にまとめて置いている」旨を一言明記すること。

### 第9章（9-4メモ）

- 第3〜9章で積み上げてきた要素（スイッチング、IPアドレス、ルーティング、VLAN、トランスポート層、
  ACL/NAT、冗長化）がどう組み合わさって実際のネットワークになるかを、2層・3層ネットワーク
  アーキテクチャの図で総括する章末セクション。

### 第10章

- 冒頭の幕間「名前を教え合う話」は、以下の流れを本文化する。

  - 自分たちの中だけの名前解決（hosts的発想）で足りていた
  - 外部参照が必要になった → ルートDNSへの伏線

### 第11章（11-1メモ: QUIC）

- HTTPS節でHTTP/3・QUICに触れるかどうかは【検討中】。触れる場合も「UDPベースの新しい
  トランスポート」という概要止まりとし、輻輳制御などの詳細には立ち入らない。

### 第12章（12-3: 暗号化の深さ／12-4メモ: VPN・ZTNA）

- 暗号化は「なぜ必要か」「どこで使われているか」の整理までとし、暗号アルゴリズムの数学的な
  仕組みは扱わない（決定ログ#7）。
- VPN（IPsec/SSL-VPN）とZTNAの対比を扱う。ZTNAへの移行トレンドについて具体的な事実・数値を
  引用する場合は、執筆時に一次情報の出典を明記すること（本メモの時点では未確定・要出典）。
